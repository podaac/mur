Running on MAAP

The same container images, submitted as cloud jobs instead of local Docker — and an honest account of how far that is wired up.

What it means here

The container images do not change. Because every input is a named flag whose value may be a local path or an s3:// href, the same image runs unmodified in both environments; only the orchestrator differs. run_mur_pipeline.py resolves host paths and bind-mounts them; run_mur_maap.py resolves s3:// hrefs and submits jobs.

Each entrypoint sources a shared helper that fetches s3:// values into local scratch before MATLAB starts. Local paths pass through untouched. Nothing in the MATLAB code knows which environment it is running in.

Fan-in

Stages with a variable number of inputs — L2P's granules, MRVA's per-sensor observation files across a multi-day window — cannot use a repeated flag, because the job submission interface takes a fixed set of named parameters. They take a manifest instead: a small JSON file listing exactly the files this run needs, each entry carrying the path or href plus enough metadata to reconstruct the directory layout MATLAB expects.

That indirection is what lets an unbounded fan-in travel through a fixed-arity interface, and it works identically on both backends.

Current state

The MAAP path is partially implemented. The contract, the manifest mechanism and the localization helper are real and exercised by the local pipeline every run. The job submission and output-retrieval layer is still a stub, and cross-run output discovery — MRVA finding the previous day's coefficients produced by an earlier job — depends on a cataloguing mechanism that has not been designed yet.

In practice that means the containers are ready for the environment but the orchestration around them is not finished. Treat run_mur_maap.py as the shape of the intended solution rather than something deployable today.

The per-container status table, the confirmed submission mechanism and what remains are in MAAP_EXECUTION.md. The contract itself is in INPUT_CONTRACT.md.
