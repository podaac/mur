Requirements

A candidate instrument must supply GHRSST L2P NetCDF granules through PO.DAAC, carrying SST, quality level, and per-pixel uncertainty. Without a usable quality flag and error estimate there is no principled way to weight the observations against the existing sensors.

The four parameters that matter

La and Lb
The scale band the sensor contributes to. Lb should reflect what the instrument can genuinely resolve — a 25 km microwave footprint stops around L=8, a 1 km infrared imager can run to L=12. Setting Lb too high injects noise into fine scales as though it were signal.
day_range
How many days either side of the analysis day are pulled in. Wider windows help sparse or heavily cloud-affected sensors and cost processing time.
stable
Days after which that sensor's data for a given day is considered settled and will no longer be reprocessed. Set it from the provider's actual latency, not optimistically — too low and the pipeline freezes an incomplete day.

Integration steps

  1. Assess suitability — resolution, coverage, latency, and whether quality and uncertainty fields are usable.
  2. Add the sensor table entry so the L2P reader knows the granule's variable names and quality conventions.
  3. Add it to the configuration — collection name, region, La/Lb, day_range, stable, and a start date.
  4. Verify the binary output for a known day before enabling it in the analysis.
  5. Compare analyses with and without the sensor to confirm it improves rather than perturbs the field.

Configuration shape

"SENSOR": {
  "collection_name": ["PODAAC-COLLECTION-ID"],
  "start_date": "2026-01-01T00:00:00Z",
  "region": "Global",
  "La": 2,
  "Lb": 9,
  "day_range": [2, 2],
  "stable": 2,
  "description": "Instrument, platform"
}
